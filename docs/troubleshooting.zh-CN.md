# 故障排查

[English](troubleshooting.md)

按这个顺序查看：

1. **PR 评论。** 引擎认出原因时，评论会写明原因（即下面的原因码）以及怎么修。
2. **工作流运行。** 在 PR 的 Checks 标签页打开 deploy 任务：失败的那个 action 步骤会显示错误，它后面的 **Diagnostics** 步骤会输出环境的状态。
3. **在主机上**，`tailnet-preview doctor <env>`（`main`、`pr-<编号>` 或 `br-<分支>`）随时都能输出同样的状态：容器、Tailscale 节点或共享入口、HTTPS 证书是否可用、各个上游是否有响应，以及最近的日志。

## 引擎能识别的失败

| 原因码         | 现象                                                                                                                                                                                       | 原因                                                                                                                           | 处理                                                                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config`       | 部署立即失败                                                                                                                                                                               | `.tailnet-preview/` 无效（未知的键、缺少文件、`HTTP` 写错）                                                                    | 按提示信息修正（[design.md 第 5 节](design.zh-CN.md#5-项目配置)）                                                                                                                                                                            |
| `registry`     | 拉取镜像时 `connection reset by peer`，重试后仍失败                                                                                                                                        | 主机到 Docker Hub 的链路                                                                                                       | 给 Docker 守护进程配置代理或镜像加速（[host-setup.md](host-setup.zh-CN.md#2-主机一次)），用 `docker pull` 验证                                                                                                                               |
| `build`        | 镜像构建失败                                                                                                                                                                               | 拉取基础镜像失败（同上），或编译错误                                                                                           | 看构建步骤的输出                                                                                                                                                                                                                             |
| `ts_secret`    | `no TS_OAUTH_SECRET`                                                                                                                                                                       | 主机配置和仓库 secret 里都没有                                                                                                 | [host-setup.md](host-setup.zh-CN.md#2-主机一次) 第 2.4 步                                                                                                                                                                                    |
| `ts_login`     | sidecar 两分钟内没有登录                                                                                                                                                                   | OAuth 密钥已撤销或过期，或 `tagOwners` 里缺少 `tag:preview`                                                                    | `docker logs <project>-<env>-ts-1`                                                                                                                                                                                                           |
| `https`        | 一切都在运行，部署却"失败"；浏览器报告 TLS 握手被重置；`tailscale cert` 提示 `does not support getting TLS certs`                                                                          | tailnet 没有开启 HTTPS 证书                                                                                                    | 管理后台 → DNS → 开启 MagicDNS 和 HTTPS，然后执行 `tailnet-preview compose <env> restart ts`。环境已保留，下次部署会升级它                                                                                                                   |
| `cert`（提示） | PR 评论说"试用环境已就绪"，并注明"HTTPS 证书申请中"；浏览器连不上（`curl` 报告连接被拒绝）；原因里写着 `NXDOMAIN`、`Incorrect TXT record`、`SetDNS ... deadline exceeded` 或 `rateLimited` | 部署期间 Let's Encrypt 没有签发这个节点的证书：Tailscale 的 DNS 验证记录还没传播到公网 DNS，或者一小时内这个名字有五次验证失败 | 等待：sidecar 会在 6、26、71 分钟后重新申请，之后一天内每小时一次；每次距上次失败至少 6 分钟，并且等频率限制解除（`tailnet-preview doctor <env>` 显示每次尝试）。拿到证书后就提供 HTTPS。这是 Tailscale 证书服务的问题，不是主机或项目的问题 |
| `fork`         | 复制基线数据失败                                                                                                                                                                           | `DATA_VOLUMES` 里有一项不是 `compose.yaml` 中的数据卷，或者基线已损坏                                                          | 修正 `DATA_VOLUMES`；执行 `tailnet-preview doctor main`                                                                                                                                                                                      |
| `migrate`      | 迁移任务失败                                                                                                                                                                               | 迁移本身有错，或者某个迁移在这个环境里执行过之后又被修改                                                                       | 修好它；如果是改过的迁移，执行 `tailnet-preview reset pr-<n>`                                                                                                                                                                                |
| `seed`         | 演示数据任务失败                                                                                                                                                                           | 演示数据命令出错                                                                                                               | 看它的输出                                                                                                                                                                                                                                   |
| `health`       | `HEALTH_PATH` 两分钟内没有响应                                                                                                                                                             | 应用启动失败，或 `HTTP`/`HEALTH_PATH` 指错了地方                                                                               | 运行日志里打印了各服务的日志                                                                                                                                                                                                                 |

## 其他现象

| 现象                                                   | 原因                                                                                                               | 处理                                                                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| PR 说已就绪，但浏览器提示找不到网站                    | 你访问用的设备没用 Tailscale DNS（关闭了"Use Tailscale DNS"，或用了 `--accept-dns=false`）。主机看不到这一点       | 在那台设备的 Tailscale 客户端里打开它；`tailscale ping <project>-<env>` 应当有响应                                   |
| 浏览器完全连不上（超时）                               | tailnet 的访问策略不允许你的设备访问 `tag:preview` 的这个端口                                                      | [host-setup.md](host-setup.zh-CN.md#1-tailnet一次) 第 2 步                                                           |
| job 一直在等 runner                                    | 没有标签为 `preview` 的 runner 服务这个仓库，或者 runner 离线                                                      | Settings → Actions → Runners；或者取消设置 `PREVIEW_ENABLED`                                                         |
| "没有创建试用环境"                                     | PR 环境已达 `MAX_ENVS` 个，或者可用内存低于 `MIN_FREE_MB`                                                          | 关掉不需要的 PR，再推送一次                                                                                          |
| 共享入口：名字解析不了                                 | tailnet 里没有 `TP_INGRESS_DOMAIN` 的 split DNS 条目，访问策略没有放行到入口的 53 端口，或者设备没用 Tailscale DNS | 主机设置第 4 节；在 tailnet 里的设备上执行 `dig <name> @<ingress address>`                                           |
| 共享入口：浏览器出现证书警告                           | 通配符证书还没签下来（Traefik 在用它自己的证书）                                                                   | `tailnet-preview doctor <env>` 会显示 Traefik 的 ACME 消息；通常是 DNS token 的权限或 `TP_INGRESS_ACME_EMAIL` 的问题 |
| 地址以 `-1` 结尾（`myapp-pr-42-1.…`）；提示 `hostname` | tailnet 里另一台设备占用了这个环境的名字，通常是之前某个环境的节点一直没退出登录                                   | 在管理后台（Machines）删除旧设备，把这台改名为 `<project>-<env>`，然后再推送一次；下次部署会用上这个地址             |
| 第一个 PR 没有从基线复制                               | 正常：默认分支还没用上 tailnet-preview                                                                             | 合并它；之后的 PR 都会复制基线                                                                                       |
| 改了旧迁移后，PR 环境里的数据是旧的                    | 迁移只会向前执行                                                                                                   | `tailnet-preview reset pr-<n>`                                                                                       |
| 已关闭 PR 的环境还在                                   | PR 关闭时主机离线                                                                                                  | 每晚的任务会删除它们；或者执行 `tailnet-preview prune <open PR numbers>`                                             |
