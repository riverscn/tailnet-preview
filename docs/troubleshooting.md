# Troubleshooting

Start with the PR comment (it names the cause when the engine recognizes it) and the **diagnostics** step
of the workflow run. On the host, `tailnet-preview doctor <env>` prints the same: containers, the Tailscale
node, whether HTTPS certificates are available, the serve configuration, whether each upstream answers
from inside the sidecar, and recent logs.

## Failures the engine recognizes

| Reason      | Symptom                                                                                                                                    | Cause                                                                                                             | Fix                                                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config`    | Deploy fails immediately                                                                                                                   | Invalid `.tailnet-preview/` (unknown key, missing file, bad `HTTP`) or a failing `db-init.sql` / `db-created.sql` | Fix what the message names ([design.md section 5](design.md#5-project-configuration))                                                                   |
| `registry`  | `connection reset by peer` while pulling, after retries                                                                                    | The host's link to Docker Hub                                                                                     | Proxy or registry mirror for the Docker daemon ([host-setup.md](host-setup.md#2-the-machine-once)), check with `docker pull`                            |
| `build`     | Image build fails                                                                                                                          | Base image pull (as above) or a compile error                                                                     | Read the build step                                                                                                                                     |
| `ts_secret` | `no TS_OAUTH_SECRET`                                                                                                                       | Neither the host configuration nor a repository secret                                                            | [host-setup.md](host-setup.md#2-the-machine-once) step 3                                                                                                |
| `ts_login`  | Sidecar did not log in within two minutes                                                                                                  | OAuth secret revoked or expired, `tag:preview` missing from `tagOwners`                                           | `docker logs <project>-<env>-ts-1`                                                                                                                      |
| `https`     | Deploy "fails" although everything runs; browsers report a reset TLS handshake; `tailscale cert` says `does not support getting TLS certs` | HTTPS certificates are not enabled for the tailnet                                                                | Admin console → DNS → enable MagicDNS and HTTPS, then `tailnet-preview compose <env> restart ts`. The environment was kept; the next deploy upgrades it |
| `migrate`   | The migrate task fails                                                                                                                     | A broken migration, or a migration edited after it ran in this environment                                        | Fix it; for an edited migration, `tailnet-preview reset pr-<n>`                                                                                         |
| `seed`      | The seed task fails                                                                                                                        | The seed command                                                                                                  | Read its output                                                                                                                                         |
| `health`    | `HEALTH_PATH` did not answer within two minutes                                                                                            | The application fails at startup, or `HTTP`/`HEALTH_PATH` point to the wrong place                                | Service logs are printed in the run                                                                                                                     |

## Other symptoms

| Symptom                                                        | Cause                                                                                                                              | Fix                                                                                          |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| The PR says ready, but the browser cannot find the site        | The device you browse from does not use Tailscale DNS ("Use Tailscale DNS" off, or `--accept-dns=false`). The host cannot see this | Turn it on in that device's Tailscale client; `tailscale ping <project>-<env>` should answer |
| The browser cannot connect at all (timeout)                    | The tailnet policy does not let your device reach `tag:preview` on that port                                                       | [host-setup.md](host-setup.md#1-the-tailnet-once) step 2                                     |
| The job waits for a runner forever                             | No runner labelled `preview` serves this repository, or it is offline                                                              | Settings → Actions → Runners; or unset `PREVIEW_ENABLED`                                     |
| "No preview environment was created"                           | `MAX_ENVS` PR environments exist, or available memory is below `MIN_FREE_MB`                                                       | Close PRs you do not need, push again                                                        |
| The first PR was not copied from a baseline                    | Expected: the default branch does not use tailnet-preview yet                                                                      | Merge it; the next PRs are copied                                                            |
| A PR environment has stale data after editing an old migration | Migrations only move forward                                                                                                       | `tailnet-preview reset pr-<n>`                                                               |
| Environments of closed PRs remain                              | The host was offline when the PR closed                                                                                            | The nightly job removes them; or `tailnet-preview prune <open PR numbers>`                   |
